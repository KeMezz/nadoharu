## ADDED Requirements

### Requirement: `/posts` 타임라인은 인증 사용자에게 커서 기반 무한 스크롤을 제공해야 한다

시스템은 인증 사용자에게 `/posts` 화면에서 커서 기반 타임라인 목록을 제공해야 한다(MUST). 초기 진입 시 첫 페이지를 로드하고, 하단 도달 시 다음 커서 페이지를 이어붙여야 한다(MUST). 더 이상 페이지가 없으면 추가 요청을 중단해야 한다(MUST). 다음 페이지 요청이 실패하면 기존 목록을 유지하고 재시도 가능한 오류 상태를 제공해야 한다(MUST).

#### Scenario: 인증 사용자의 첫 페이지 조회

- **WHEN** 인증된 사용자가 `/posts` 화면에 처음 진입한다
- **THEN** 시스템은 첫 커서 페이지를 조회하고 게시물 목록을 표시한다

#### Scenario: 하단 도달 시 다음 페이지 조회

- **WHEN** 인증된 사용자가 목록 하단에 도달하고 `hasNextPage`가 `true`다
- **THEN** 시스템은 `endCursor`를 사용해 다음 페이지를 조회하고 기존 목록 뒤에 이어붙인다

#### Scenario: 하단 도달 후 다음 페이지 요청 실패

- **WHEN** 인증된 사용자가 목록 하단에 도달해 다음 페이지를 요청했지만 네트워크 오류가 발생한다
- **THEN** 시스템은 기존 목록을 유지하고 재시도 가능한 오류 상태를 표시한다

#### Scenario: 더 이상 페이지가 없는 경우

- **WHEN** 타임라인 응답의 `hasNextPage`가 `false`다
- **THEN** 시스템은 추가 페이지 요청을 보내지 않는다

### Requirement: 타임라인 정렬은 최신순으로 고정되어야 한다

시스템은 `/posts` 타임라인을 최신순(`createdAt DESC`, tie-breaker `id DESC`)으로 표시해야 한다(MUST). 사용자가 정렬 방식을 변경할 수 있는 UI를 제공하지 않아야 한다(MUST).

#### Scenario: 최신 게시물이 먼저 표시됨

- **WHEN** 생성 시각이 다른 게시물이 타임라인에 존재한다
- **THEN** 시스템은 가장 최근 `createdAt` 게시물을 먼저 표시한다

#### Scenario: 생성 시각이 같은 게시물 순서 고정

- **WHEN** 동일한 `createdAt` 값을 가진 게시물이 여러 개 존재한다
- **THEN** 시스템은 `id` 내림차순으로 고정된 순서를 유지한다

#### Scenario: 정렬 옵션 비노출

- **WHEN** 사용자가 `/posts` 화면을 본다
- **THEN** 시스템은 정렬 변경 UI를 노출하지 않는다

### Requirement: 비인증 사용자의 `/posts` 접근에는 로그인 안내 UX를 제공해야 한다

시스템은 비인증 사용자가 `/posts`에 접근하면 타임라인 데이터 대신 로그인 안내 UI를 표시해야 한다(MUST). 시스템은 비인증 상태에서 `posts` 쿼리를 호출하지 않아야 한다(MUST). 안내 UI는 로그인 이동 동작을 제공해야 한다(MUST).

#### Scenario: 비인증 사용자의 `/posts` 접근

- **WHEN** 비인증 사용자가 `/posts`에 접근한다
- **THEN** 시스템은 로그인 안내 메시지와 로그인 이동 버튼을 표시한다

#### Scenario: 비인증 사용자의 `/posts` 접근 시 타임라인 쿼리 생략

- **WHEN** 비인증 사용자가 `/posts`에 접근한다
- **THEN** 시스템은 `posts` 쿼리를 실행하지 않고 로그인 안내 UI를 표시한다

#### Scenario: 로그인 이동 버튼 선택

- **WHEN** 비인증 사용자가 로그인 이동 버튼을 누른다
- **THEN** 시스템은 `/login`으로 이동한다
