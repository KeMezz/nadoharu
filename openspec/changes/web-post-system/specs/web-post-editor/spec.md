## ADDED Requirements

### Requirement: 게시물 작성/수정 폼은 핵심 입력 필드와 검증을 제공해야 한다

시스템은 게시물 작성/수정 폼에서 본문 텍스트, 보조 텍스트(subcontent), 이미지 입력을 제공해야 한다(MUST). 유효하지 않은 입력 상태에서는 제출을 차단하고 검증 메시지를 노출해야 한다(MUST).

#### Scenario: 필수 입력 누락 상태에서 제출 시도

- **WHEN** 사용자가 필수 입력 없이 작성/수정 제출을 시도한다
- **THEN** 시스템은 제출을 차단하고 검증 오류를 표시한다

#### Scenario: 유효한 입력으로 작성 제출

- **WHEN** 사용자가 유효한 입력값으로 게시물 작성을 제출한다
- **THEN** 시스템은 생성 요청을 전송한다

### Requirement: 카테고리 입력은 이번 범위에서 비활성화되어야 한다

시스템은 게시물 작성/수정 화면에서 카테고리 입력 UI를 노출하지 않아야 한다(MUST). 시스템은 게시물 작성/수정 요청의 카테고리 값을 빈 값으로 고정해야 한다(MUST).

#### Scenario: 작성/수정 폼에서 카테고리 입력 미노출

- **WHEN** 사용자가 게시물 작성 또는 수정 폼을 연다
- **THEN** 시스템은 카테고리 입력 컨트롤을 표시하지 않는다

#### Scenario: 작성/수정 제출 시 카테고리 빈 값 고정

- **WHEN** 사용자가 게시물 작성 또는 수정을 제출한다
- **THEN** 시스템은 카테고리를 빈 값으로 설정해 요청한다

### Requirement: 게시물 작성/수정 제출 상태를 사용자에게 명확히 표시해야 한다

시스템은 작성/수정 제출 과정에서 로딩, 성공, 실패 상태를 명확히 표시해야 한다(MUST). 성공 시 사용자가 결과를 확인할 수 있는 화면으로 이동시켜야 한다(MUST).

#### Scenario: 제출 중 로딩 상태 표시

- **WHEN** 사용자가 작성/수정 제출 버튼을 누른다
- **THEN** 시스템은 중복 제출을 막고 로딩 상태를 표시한다

#### Scenario: 제출 성공 처리

- **WHEN** 작성/수정 요청이 성공한다
- **THEN** 시스템은 성공 상태를 반영하고 게시물 상세 또는 목록으로 이동한다

#### Scenario: 제출 실패 처리

- **WHEN** 작성/수정 요청이 실패한다
- **THEN** 시스템은 실패 메시지와 재시도 가능한 상태를 표시한다

### Requirement: 게시물 수정 권한 실패는 401/403 상태를 구분해 표시해야 한다

시스템은 게시물 수정 요청 실패 시 인증 실패(401)와 권한 부족(403)을 구분해 안내해야 한다(MUST). 401은 재인증 동작을, 403은 권한 없음 안내를 제공해야 한다(MUST).

#### Scenario: 수정 요청이 401로 실패

- **WHEN** 사용자가 게시물 수정을 시도했지만 서버가 401을 반환한다
- **THEN** 시스템은 로그인 필요 메시지와 로그인 이동 동작을 표시한다

#### Scenario: 수정 요청이 403으로 실패

- **WHEN** 사용자가 게시물 수정을 시도했지만 서버가 403을 반환한다
- **THEN** 시스템은 수정 권한 없음 메시지를 표시한다
